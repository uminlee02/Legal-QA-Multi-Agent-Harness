# LangGraph 하네스 평가 결과 (PHASE 8)

**연구 질문(§8):** 큰 모델(Qwen3.5-27B)에 검증된 하네스(LangGraph) + 표준 스킬(IRAC/CoVe/ReAct)
+ 사실검증 게이트(법제처) + 이종 교차검증(DeepSeek-R1)을 얹으면 인용 정확성이 오르는가?

**설정:** KoBLEX n=226, gen=Qwen3.5-27B, logic=DeepSeek-R1-Distill-Qwen-32B, 채점=법제처 Open API +
frozen lawcheck v1 + KoBLEX gold. temp=0, seed=42. 결과 파일 `results/lg_eval_n226_both.json`.

## 해석 (핵심 발견)

- **RAG가 정확성 개선의 거의 전부를 담당한다.** ①→②에서 엄격 60.1%→4.1%(**−93%**), gold 12%→49%(4배).
  큰 모델도 근거 없이는 조문 내용을 60% 오적시하나, 검색 접지만으로 4%대로 붕괴.
- **검증에 근거를 주면(③→④) '재생성 부작용'이 부분적으로 완화된다.** 내용불일치 **11→8**, 엄격 **5.6%→5.3%**.
  DeepSeek가 자기 지식 대신 조문 원문과 대조하니 잘못된 revise가 줄어 부작용이 소폭 감소(가설 방향 지지).
  단, 근거 검증은 재생성을 오히려 **더** 유발(158→207) — 근거 대조로 더 엄격히 revise하나, 그 재생성이
  가짜율 저감으로 이어지지는 않음(churn).
- **근거 검증(④)조차 RAG 단독(②)을 못 이긴다.** 엄격 ② 4.1% < ④ 5.3%. 근거를 줘도 **전체 재생성**을 쓰는 한
  멀티에이전트가 RAG 단독을 넘지 못한다.
- **★ 그러나 재생성을 '타겟 편집'으로 바꾸면(⑥) 멀티에이전트가 RAG 단독을 이긴다.**
  ⑥ 느슨 **1.6%**·엄격 **2.7%** — ②(3.7/4.1%)보다 **35~58% 낮고**, ③(3.6/5.6%)보다 **52~57% 낮다.**
  전이 분석이 기전을 확증: ③ 재생성은 순 **−9**(고침3/깸12), ⑥ 타겟편집은 순 **+2**(고침9/깸7) — **부호가 뒤집힌다.**
  틀린 줄만 국소 수정(평균 편집률 14%)하니 정상 인용을 안 깨고(whack-a-mole 제거) 법제처가 잡은 가짜만 제거·정정.
- **최종 결론(수정):** 정확성의 1차 동인은 여전히 **생성 시점 RAG 접지**(①→② −93%). 그러나 멀티에이전트 검증이
  무용한 게 아니라, **개입 방식이 문제였다.** "검증 실패 → 전체 재생성"은 부작용(신규 환각)으로 순손실이지만,
  "검증 실패 → 틀린 span만 국소 편집"은 **RAG 단독마저 넘어선다**(엄격 4.1%→2.7%). 즉 **멀티에이전트 검증은
  국소 편집(surgical repair)과 결합할 때 비로소 이득**이 된다(문헌 DISC/PDB/DETECT-REMASK-REPAIR과 일치).

## Sanity 앵커 (기존 프로젝트 표와 정합)

- 순수 베이스라인 엄격 60.1% ≈ 기존 맨몸(Qwen2.5-7B) 63.6% — 큰 모델도 맨몸 내용환각률 비슷(모델 크기로 안 풀림).
- 제안 느슨 3.6%/엄격 5.6% ≈ 기존 RAG(Qwen2.5-7B) 5.3%/6.4% — 접지가 핵심 동인이라는 프로젝트 주제 재확인.
  단, gold recall 49% ≫ 기존 17% → **큰 모델 + 하네스가 접지 위에서 근거 활용을 크게 개선**.

## 방법 메모

- **베이스라인 = 완전 순수**(검색도 제거, `--baseline-rag off`, §8): 하네스+스킬+검증+게이트+이종검증 전부 제거.
  두 조건 대비 = "하네스+스킬+검증의 총 효과". (RAG 공통 설계는 바닥효과로 대비 소멸 → 순수 대비 채택.)
- **채점 동결:** frozen `rates/fr/gold_recall`(run_koblex) + KoBLEX gold 재채점. 그래프 내부 검증(RAG 접지 gold)과
  평가 채점(annotated gold)을 구분. lawcheck v1 판정 불변.
- **복원력:** 법제처 간헐 404 → ResilientVerifier 4회 재시도 후 uncertain 폴백(분모 제외). 문항별 체크포인트/재개.
  최종 런 오류 문항 0건.
